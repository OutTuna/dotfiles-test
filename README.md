# Linux dotfiles

Ветка `linux` повторяет настройки Neovim и оформление терминала из ветки `macos` (23 октября 2026 года). Системные пути и сочетания Kitty адаптированы под Linux.

- **Neovim / LazyVim:** идентичные macOS конфигурация и версии плагинов. Угольная палитра Gruvbox, дерево файлов слева, выбор Python venv в нижней строке, C/C++, CMake, C#, Python, Git, Markdown и YAML. Отключены стартовый экран, Noice, плавная прокрутка и часы в статусной строке.
- **Fish / Starship:** такое же приглашение и команды `dc`, `cfg`, `acfg`, `c`, `cls`, `up`, `sns`, `zsns`. Starship заменяет прежнюю загрузку Oh My Fish. Необязательные fastfetch, Rust и LM Studio подключаются только при наличии.
- **Kitty:** JetBrainsMono Nerd Font Mono, размер 16, такие же цвета и вкладки; `Ctrl+Shift` вместо macOS `Command`.

## Установка

Установите через пакетный менеджер своего дистрибутива:

- Neovim **0.11.2 или новее**, Git, Fish, Kitty, Starship;
- JetBrainsMono Nerd Font Mono;
- ripgrep, fd, curl, unzip, tar, gzip, Node.js и npm;
- C/C++-компилятор, make, CMake и Python 3 с поддержкой venv;
- .NET SDK 8 для проверенной C#-конфигурации;
- `wl-clipboard` для буфера обмена в Wayland либо `xclip`/`xsel` в X11;
- fastfetch — по желанию.

Если `fd` в вашем дистрибутиве называется `fdfind`, обеспечьте доступность команды `fd` через локальную ссылку или настройку пакета. Версии пакетов различаются между дистрибутивами: проверьте `nvim --version` и `dotnet --info`.

Перед копированием сохраните свои конфиги. Перенесите нужные каталоги из `.config/` в `~/.config/`, затем перезапустите терминал. Kitty использует `fish` из `PATH`. Для самостоятельного запуска Neovim в другом терминале смена оболочки по умолчанию не требуется.

При первом запуске Neovim загрузит плагины. Выполните `:Lazy restore`, чтобы использовать версии из `lazy-lock.json`. Языковые серверы устанавливает Mason; при необходимости выполните `:MasonInstall clangd omnisharp pyright ruff`. Интернет нужен для первоначальной установки плагинов и инструментов.

## Основные сочетания Neovim

Все сочетания ниже — в NORMAL (`Esc`):

| Клавиши | Действие |
| --- | --- |
| `i` / `Esc` | Начать ввод / вернуться в NORMAL |
| `:w` + Enter | Сохранить |
| `Space e` | Показать или скрыть дерево файлов |
| `Space Space` | Найти файл |
| `Space /` | Найти текст в проекте |
| `Space c v` | Выбрать существующее Python-окружение |
| Клик по `venv:` внизу | Открыть выбор окружения |
| `K` / `gd` | Документация / переход к определению |
| `Space b d` | Закрыть текущий файл |

Пробел и последующие буквы нажимаются последовательно. Выбранный venv применяется к языковым инструментам и новым терминалам Neovim; уже открытые терминалы нужно открыть заново. Создание окружения: `python3 -m venv .venv`.

## Проекты C++ и C#

Для CMake-проекта:

```sh
cmake -S . -B build -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
```

clangd находит базу в стандартном каталоге `build`. Для другой папки создайте в конкретном проекте `.clangd`:

```yaml
CompileFlags:
  CompilationDatabase: build-debug
```

База должна содержать актуальные параметры и пути к установленным зависимостям. Локальные базы, окружения и пути отдельных проектов в dotfiles не входят. Проверка Windows-веток кода требует подходящей Windows-среды или корректно настроенного кросс-компилятора с Windows-заголовками.

C# открывайте из папки с `.sln` или `.csproj`. OmniSharp использует `DOTNET_ROLL_FORWARD=Major` только для своего процесса; целевые версии SDK/runtime проектов остаются прежними. Проекты с другими версиями .NET могут требовать дополнительные SDK/runtime. Windows-зависимые приложения не становятся Linux-приложениями от смены редактора.

`sns` и `zsns` требуют личных записей в `~/.ssh/config`; ключи и параметры подключения не хранятся в репозитории. `fish_variables`, история, кэши и резервные копии также не включены.

## Проверка изменений

Конфигурация Neovim побайтово совпадает с macOS-веткой. Проверены её загрузка, параметры темы и языковых серверов, а также синтаксис Fish и TOML. Проверки выполнены на macOS; запуск графического терминала и установку пакетов на Linux нужно проверить на целевой машине.
